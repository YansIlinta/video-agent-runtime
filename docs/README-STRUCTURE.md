# README structure

The root README is intentionally organized as a product home rather than a package reference.

Its information hierarchy is inspired by product-oriented open-source projects such as `chthollyphile/folia-major`: show what the product is and what using it feels like before sending readers into implementation details.

The sections are expected to stay in roughly this order:

1. Product name, tagline, badges and navigation.
2. Short product description and explicit non-goal.
3. A visible workflow / showcase of what a normal run looks like.
4. Core capability table.
5. Speech / ASR / TTS / voice identity capabilities.
6. Agent-facing surfaces and MCP connection path.
7. Quick start and provider configuration.
8. Real-provider acceptance / benchmark path.
9. Mobile host story and current verification boundary.
10. Architecture summary.
11. Technical documentation index.
12. Project status, security principles and license.

Do not move detailed model comparisons, architecture rationale, mobile audits, or benchmark methodology back into the root README. Link to the relevant `docs/` page instead.

Do not add screenshots, performance claims or support badges that are not backed by actual repository artifacts or measured evidence.
