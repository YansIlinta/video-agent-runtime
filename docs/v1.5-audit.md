# V1.5 implementation audit

Audited 2026-08-24 before V1.5 changes. Scope: all authored TypeScript/Python, tests, scripts, MCP/CLI adapters, package/configuration files, and existing documentation. Generated `dist`, `node_modules`, demo artifacts, and release archives were inspected only as build products.

## Existing domain types

`packages/core/src/schemas.ts` is the canonical Zod boundary and uses schema version 1. It defines Project, Asset and MediaMetadata; WordTimestamp, TranscriptSegment, Transcript and TranscriptQualityReport; EditingStrategy and EditPlan; Timeline, Track and Clip; Feedback and Diagnosis; WorkflowRun/WorkflowStep; SpeechAsset and VoiceProfile; Operation, EditDiff and ProjectVersion. Time is integer, non-negative microseconds. Transcript raw, normalized, and display text are already distinct.

The existing model is sufficient. V1.5 should add EditPatch, Job, provider-call metadata, alignment/diarization/visual evidence records, and configuration types alongside these entities. It should not replace Project, Timeline, Workflow, or Version.

## Provider interfaces

`packages/providers/src/contracts.ts` currently separates ASR, TTS, LLM and Renderer. ASR already advertises word/segment timestamps, speaker diarization, language detection, confidence and forced alignment. TTS already advertises selection, cloning, speed, timestamps and alignment capabilities. Renderer accepts only a validated Timeline plus a project-scoped asset resolver.

The LLM interface is narrower: two task-specific methods return domain objects directly and do not expose capabilities, request metadata, generic schema-bound generation, cancellation, retry or Patch Planner. V1.5 can preserve the two existing methods while adding `generateStructured`, call metadata and `createEditPatch`.

No alignment, diarization, visual-evidence, provider-health, progress, or cancellation contracts exist yet.

## Persistence boundaries

`ProjectStore` is the single project persistence boundary. JSON writes use a same-directory temporary file, fsync, backup rename and recovery. Project IDs and resolved paths are contained under the configured workspace. Source media is copied, size-checked and hashed. Mutation methods exist for project, timeline, workflow, transcript, strategy, plan, version, feedback, diagnosis and speech records. Applied versions are immutable JSON files. A project lock serializes mutations.

Gaps: no first-class jobs/events/patches/evidence/provider-call records; no lookup by ASR/TTS cache key; no stale-lock recovery; no project-scoped temp helper or startup sweep; source hashing currently reads the complete file into memory; multi-file commits are ordered but not journaled as one transaction.

## Workflow state machine

The product workflow is explicit from CREATED through ingest/transcribe/analyze/propose/approve/plan/validate/apply/preview/review/feedback/diagnose/patch/replan/final approval/export/DONE, with FAILED recovery transitions. `runStep` persists a running step before work, then completion or failure. `recover` marks an interrupted running step FAILED.

This is sufficient as the product state machine. Job execution must remain separate: Workflow says what the product is doing; Job says how a long operation is executing.

## Render pipeline

`FFmpegRenderer` compiles Timeline clips to an argument-array FFmpeg filter graph. It trims/retimes/scales/pads/concatenates video and original audio, mixes narration, applies explicit side-chain ducking, burns SRT captions, supports a requested preview range, selects preview/final profiles, probes the result and runs a preview self-check.

Gaps: direct final-path rendering, `-y`, no atomic finalize, cancellation or normalized progress, captions are not cleaned up, range captions are not rebased, environment lookup lives in the renderer, failure classification is textual, and process termination has no graceful-then-force policy.

## Fake providers

FakeASR creates deterministic timed words and 10-word segments from the prompt, including one speaker and confidence. FakeLLM proposes a hook-first strategy and ranks transcript segments by character/time density to build a deterministic EditPlan. FakeTTS writes a deterministic tone with synthetic word timings. FakeRenderer writes a JSON marker rather than media. These provide a stable Level-1 CI path and must remain the default.

## MCP contracts

The stdio server exposes 33 project-scoped task tools. They cover project create/open/status, media import/inspect, ASR/transcript, timeline inspection, strategy approval, EditPlan create/validate/diff/apply/revert, preview, feedback/diagnosis/replan, versions, TTS fit/voices/narration, final approval and export. Tools return both text and `structuredContent`; failures set `isError`. The server does not expose shell or raw FFmpeg controls.

V1.5 additions should be limited to `system_status`, `job_status`, `job_list`, `job_cancel`, `edit_patch_plan`, `edit_patch_diff`, `edit_patch_apply`, `transcript_quality`, and `visual_inspect_range`.

## CLI contracts

The CLI mirrors the core workflow: create/status/import/transcribe/transcript/propose/approve/plan/validate/diff/apply/preview/feedback/diagnose/replan/narration/versions/restore/approve-final/export. It is a thin argument adapter over `VideoAgentCore`. Missing production commands are doctor, jobs, cancel, patch and eval.

## Test coverage

Current required suite has 12 tests in four files. It covers integer time conversion, schema range/default behavior, EditPlan overlap/stale-version validation, deterministic timeline/diff, feedback range/category normalization, repeated structural-feedback escalation, malformed/schema-invalid provider output, timeout, TTS fit, an offline runtime workflow including caption replacement, and interrupted Workflow recovery. MCP smoke discovers tools and calls `project_create`. The FFmpeg demo generates local media and performs two previews plus final export.

Missing: structured-generation retries/metadata, PatchPlan locality/validation/reversibility, ASR cache, fusion/alignment/diarization, jobs/queue/restart/cancellation/retry/quota, FFmpeg cancellation/atomic output, doctor, MCP job tools, CLI doctor and semantic evals.

## Current recovery behavior

Atomic JSON can restore a `.bak` only when the primary file is absent. An interrupted Workflow running step becomes FAILED on the next status read. Project locks are process-created files and are always removed in a normal `finally`; there is no PID/staleness recovery. Rendering and speech use process timeouts but no caller cancellation. Queued work is not persisted, so it cannot resume after restart. Applying/restoring versions is lock-protected, but the several persisted files are not journaled for crash-after-version-before-project edge cases.

## Known TODOs and production risks

- Centralize all environment/config access and configurable quotas.
- Add a production OpenAI structured-output provider while retaining fake defaults and vendor-neutral planning roles.
- Persist provider request id, model, latency, token usage, retry count and validation result without secrets or full transcript logs.
- Implement first-class minimal EditPatch with local-scope guard and immutable version application.
- Promote faster-whisper with cache, progress and cancellation; add optional WhisperX alignment/diarization adapters and deterministic transcript fusion.
- Add optional shot/keyframe/OCR evidence and range inspection; transcript remains primary.
- Add durable FIFO jobs, bounded concurrency, per-project conflict serialization, idempotency, cancellation, classified retries and restart recovery.
- Harden subprocess/temp/output handling and expose progress.
- Add provider health/doctor, structured privacy-safe logs, semantic evaluation corpus and measured benchmark report.
- No real interview media is currently vendored; fixtures must be legally reusable or generated, with optional external local-provider runs.

## Compatibility decision

Keep schema version 1 for existing entities and add optional fields/new files so existing projects continue to parse. Keep all existing public core methods, CLI commands and MCP tool names. New workers wrap the same core operations; they do not create a second editing engine. New providers implement the existing task-specific LLM surface as compatibility methods over a generic structured-generation primitive.
